# Bilibili 直播弹幕答题

游戏服务直接连接 Bilibili 弹幕 WebSocket，不需要启动本机 `blivechat`。连接逻辑参考其直连实现；身份码模式在没有独立开放平台密钥时，仅使用 `blivechat` 公共接口换取开播凭证，弹幕数据仍由游戏服务从 Bilibili 接收。

在 `server/config.json` 的 `bilibili` 节点配置：

```json
{
  "roomId": 123456,
  "authCode": "",
  "uidBlacklist": [],
  "uidWhitelist": [],
  "allowlistMode": false
}
```

房间号和身份码可同时保留，非空身份码优先。身份码需要 Bilibili 直播开放平台授权；未配置自己的密钥时，本项目会向 `api1.blive.chat` 或 `api2.blive.chat` 发送身份码，并调用其会话开始、心跳、结束接口。该公共服务不可用时，身份码模式也不可用。若不愿使用第三方公共接口，可在 `bilibili.openLive` 填写 `appId`、`accessKeyId`、`accessKeySecret`，改走官方接口。不要将真实身份码、`SESSDATA` 或密钥提交到公开仓库。

房间号模式直接请求 Bilibili 的房间信息、WBI 签名弹幕服务器信息并连接 WebSocket。若匿名连接只返回 UID `0`，这类消息会被忽略，以免多个观众被当成同一玩家；可选配置 `bilibili.sessdata` 以使用已登录会话。身份码模式使用开放平台的 `open_id` 作为稳定身份，监控页和黑白名单中显示的也是它。

多人创建页选择“直播弹幕”，点击右侧齿轮可在新页面打开弹幕监控。使用后台密码登录后，可点击房间号打开 Bilibili 直播间，查看连接状态、实时文字弹幕和已出现用户；支持按 ID 模糊搜索，设置正常、白名单、黑名单和“仅白名单”模式。应用每次启动时“监听弹幕”Switch 默认关闭；成功创建 Bilibili 弹幕房间后自动打开，有游戏或监控订阅时建立连接。手动关闭会断开连接并停止直播答案接收。监听状态只在当前进程中生效，不写入配置；旧配置中的 `listeningEnabled` 会被忽略。黑白名单设置仍会原子更新 `server/config.json`，即时生效。

每次多人开局在 `server/logs/games` 生成一个时间戳命名的 JSONL 文件。文件包含开局、每次被游戏接受的答案提交及结局；每条提交记录题目 ID、标准答案、用户答案、判定、得分和提交后的名次。日志覆盖网页、外部接口和直播弹幕三种多人模式，目录由 Git 忽略。

多人大厅和弹幕监控页可进入“对局记录”（`/multi/records`）。使用后台密码验证后，左侧按时间浏览历史对局；右侧查看开局设置、逐条提交的用户身份、题号、答案与标准答案、正误、当时分数与名次，以及最终排名。答案记录可按用户、题目或答案搜索、按正误筛选并翻页；未结算或异常中断的日志也可以查看。列表摘要按文件更新时间缓存，详情按需逐行读取，不会一次把所有历史日志发送到浏览器。

房主创建房间并点击开始后，连接成功才开始计时。监控页可在游戏未开始时独立连接；若游戏已经连接，两者共用同一条直播连接。游戏结束停止答题，关闭最后一个监控页后断开连接。断线时自动重试。

直播对局的当前题画面会展示已接收的文字弹幕，从右向左飘过。画面左下角的弹幕按钮可调整本机显示开关、密度和透明度；设置保存在当前浏览器，不影响其他观看者，也不影响后台判题或对局日志。黑名单与仅白名单模式过滤的弹幕不会进入游戏画面。每次换题会清空上一题弹幕。

只处理普通文字弹幕；彩色文字也算普通文字。图片表情、礼物、醒目留言、镜像消息及无稳定身份的弹幕不参与。判题忽略大小写与首尾空格，同一条消息只处理一次。
