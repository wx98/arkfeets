## 1. 项目概述

- **项目名称**：粥批来猜∠
- **游戏类型**：图片猜答案小游戏
- **核心玩法**：系统展示题库维护者预先准备的局部问题图，玩家输入答案；答案命中后切换到独立的完整图片并计分。
- **运行形态**：浏览器 Web 游戏，支持单人限时闯关、多人房间抢答、外部 HTTP 接口接入答题。
- **维护方式**：题库以本地文件目录维护，不依赖数据库；提供 Web 题库管理界面辅助编辑、上传和校验。

核心原则：

1. 后端权威管理游戏状态、判题、计分和房间生命周期。
2. Vue 负责页面、表单、列表、房间大厅和管理后台。
3. Phaser 只负责游戏画面渲染、动画、倒计时视觉表现和揭晓效果。
4. 题库文件允许人工维护，但所有进入游戏的题目必须通过服务端校验。

## 2. 产品目标与版本边界

### 2.1 MVP 目标

MVP 需要能完成以下闭环：

1. 启动 Node 服务后自动读取并校验本地题库。
2. 用户可在 Web 端完成单人游戏：选择难度、题量、答题、超时扣血、结算。
3. 用户可创建多人房间：加入房间、开始游戏、实时抢答、计分、排名、结算后回到等待状态。
4. 外部系统可通过 HTTP 接口向唯一活动的外部接口房间提交答案。
5. 管理页面可浏览题库、查看校验结果、编辑题目信息、上传题目图片。

### 2.2 MVP 暂不实现

- 用户账号体系和登录注册。
- 历史战绩持久化。
- 房间跨服务进程共享。
- 复杂反作弊模型。
- 游戏回放。
- 云端对象存储。
- 自动生成题目图片。

### 2.3 关键约束

- 不使用数据库，房间和对局状态保存在内存中，服务重启后清空。
- 题库资源保存在 `./server/resource/question`。
- 单局内题目不重复。
- 题库数量不足时允许提前结束，并在结算中提示“题库已耗尽”。
- 多人模式最大 20 人。

## 3. 游戏规则

### 3.1 通用规则

- 每道题称为一个“单元”。
- 一道题可以有多个可接受答案。
- 玩家答案经过归一化后与答案列表匹配。
- 答案正确后当前单元立即结束，展示答案揭晓图。
- 同一局游戏内不会重复抽取同一道题。
- 单局题量可选：20 / 50 / 100。

答案归一化规则：

1. 删除答案中的全部空白字符后进行精确比较。
2. 不支持错别字、模糊匹配、拼音、正则表达式或自动忽略大小写。
3. 一道题的多个可接受答案统一写入 `answers`。

### 3.2 单人模式

单人模式为限时闯关。

| 难度 | 每题时间 | 初始生命 | 生命上限 |
|---|---:|---:|---:|
| 简单 simple | 90 s | 10 | 10 |
| 中等 medium | 60 s | 10 | 10 |
| 困难 hard | 30 s | 10 | 10 |
| 地狱 hell | 10 s | 10 | 10 |

规则：

1. 进入游戏时选择难度和题量。
2. 每题倒计时开始后，玩家可多次提交答案。
3. 答对：分数 +1。
4. 答错：不扣生命，只提示错误。
5. 超时且未答对：生命 -1。
6. 答对时剩余时间大于等于本题总时间的 80%，生命 +1，但不可超过生命上限。
7. 玩家可主动跳过本题；跳过按主动放弃处理，生命 -1，并进入答案揭晓。
8. 答对或主动跳过后无限时展示全图，由玩家点击“下一题”继续。
9. 生命为 0 时立即结束，不需要打完设定题量。
10. 结算展示：得分、实际出题数、正确率、剩余生命、结束原因。

结束原因枚举：

```typescript
type SoloEndReason = "COMPLETED" | "LIFE_EMPTY" | "QUESTION_EXHAUSTED";
```

### 3.3 多人房间模式

多人模式为抢答制。

规则：

1. 房主创建房间并设置房间号、题量、每题时间。
2. 玩家通过房间号加入，房间最多 20 人。
3. 仅 `IDLE` 状态允许加入。
4. 房主点击开始后房间进入 `PLAYING`，新玩家不可加入。
5. 每题所有玩家同时抢答，第一个答对者得 1 分。
6. 本题已有正确答案后，后续答案全部忽略。
7. 本题超时无人答对，则无人得分并直接进入下一题。
8. 正常题量完成后进入排名结算。
9. 最高分唯一则本局结束。
10. 最高分并列则进入加时赛。

加时赛规则：

1. 只有最高分并列玩家参与抢答。
2. 其他玩家保留在房间内，只能观看。
3. 加时赛每轮抽 1 题，答对者成为唯一胜者。
4. 若本轮超时无人答对，继续下一轮。
5. 若题库耗尽仍未分出胜负，则按并列第一结束，并提示题库不足。

### 3.4 外部 API 接入模式

外部 API 本身不是独立游戏模式，而是多人房间的一种答案来源。

- 房主创建房间时选择普通网页抢答或外部接口模式。
- 同一服务进程最多只能有一个正在游戏中的外部接口房间。
- 外部接口模式开始后，后端开放无房间号答案入口；请求只提交玩家昵称和答案。
- 外部玩家按昵称识别，不要求预先加入；首次提交时自动进入计分板。
- 网页与外部答案最终进入同一套后端判题与计分逻辑。

## 4. 核心状态机

### 4.1 房间状态

```typescript
type RoomStatus = "IDLE" | "PLAYING" | "OVERTIME" | "SETTLE";
```

| 状态 | 说明 | 允许操作 |
|---|---|---|
| `IDLE` | 等待开局 | 加入房间、退出房间、房主修改配置、房主开始 |
| `PLAYING` | 正常对局中 | 提交答案、查看计分板、玩家退出 |
| `OVERTIME` | 加时赛中 | 最高分并列玩家提交答案、查看计分板 |
| `SETTLE` | 结算展示 | 查看排名、房主跳过结算、等待自动回到 IDLE |

状态流转：

```text
IDLE -> PLAYING -> SETTLE -> IDLE
IDLE -> PLAYING -> OVERTIME -> SETTLE -> IDLE
```

### 4.2 单元状态

```typescript
type RoundStatus = "PREPARE" | "ANSWERING" | "REVEAL" | "FINISHED";
```

| 状态 | 说明 |
|---|---|
| `PREPARE` | 抽题、加载资源、广播新题基础信息 |
| `ANSWERING` | 开放答题窗口 |
| `REVEAL` | 展示答案揭晓图和正确答案 |
| `FINISHED` | 本单元完成，准备进入下一题或结算 |

### 4.3 房主处理

MVP 规则：

1. 房主主动退出、断线或会话失效时，当前房间立即解散。
2. 房间内全部玩家收到 `room:closed`，并返回游戏主界面。
3. 普通网页玩家由客户端持久化的 session ID 识别；刷新或短暂断线后使用该 ID 恢复身份。

## 5. 数据结构定义

### 5.1 单题记录

路径：`./server/resource/question_data/{questionId}.json`

```json
{
  "id": "evidence-wall-01",
  "title": "线索集合",
  "answers": ["答案1", "答案2"],
  "hint": "可选提示文本",
  "difficulty": ["simple", "medium", "hard", "hell"],
  "tags": ["角色", "剧情"],
  "originalImage": "evidence-wall.png",
  "question": {
    "x": 180,
    "y": 96,
    "width": 960,
    "height": 540,
    "sourceWidth": 1536,
    "sourceHeight": 1024
  },
  "enabled": true
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 题目稳定 ID，与文件名一致 |
| `title` | string | 是 | 管理后台和游戏展示标题 |
| `answers` | string[] | 是 | 标准答案，至少 1 个 |
| `hint` | string | 否 | 游戏中可展示的提示 |
| `difficulty` | string[] | 否 | 适用难度，缺省表示所有难度可用 |
| `tags` | string[] | 否 | 管理后台筛选用 |
| `originalImage` | string | 是 | `full_data` 中的原图文件名 |
| `question` | object | 是 | 原图像素坐标裁切框，包含位置、尺寸和原图尺寸 |
| `enabled` | boolean | 否 | 默认 true，false 时不会进入题库 |

### 5.2 题库目录 `catalogue.json`

路径：`./server/resource/catalogue.json`

```json
[
  { "id": "evidence-wall-01", "file": "question_data/evidence-wall-01.json" },
  { "id": "evidence-wall-02", "file": "question_data/evidence-wall-02.json" }
]
```

约束：

- catalogue 是轻量索引，不重复保存题目业务字段。
- 普通题目编辑只原子替换对应的单题 JSON，不重写 catalogue。
- 只有新增、删除和导入题目时才原子更新 catalogue。
- 只有注册在 catalogue 中的题目才会被校验和加载。
- 索引引用的题目若校验失败，不进入可用题库，但要出现在校验报告中。

### 5.3 原图与同名元数据

原图存放于 `./server/resource/full_data`。每张图片旁维护一个同名 JSON，作为基于该原图新增题目时的默认模板：

```text
full_data/
├─ evidence-wall.png
└─ evidence-wall.json
```

```json
{
  "name": "干员名称",
  "answers": ["干员名称", "干员别名"],
  "hint": "可选提示文本",
  "difficulty": ["simple", "medium", "hard", "hell"],
  "tags": [
    { "星级": "6星" },
    { "职业": "狙击" },
    { "分支": "速射手" },
    { "势力": "罗德岛" }
  ]
}
```

`tags` 是单键字符串对象数组，保留星级、职业、分支、位置、性别、获取途径、词缀、势力、所属国家、出身地、种族、情报编号、生日、身高、战斗经验、感染状态和上线时间等结构化属性。管理后台搜索同时匹配标签名和标签值。

从原图维度新增题目时复制答案、提示和难度，并将结构化标签转换为 `键:值` 形式的单题标签；题目标题始终初始化为空。必须填写标题并完成裁切后才允许保存。原图元数据不参与运行时判题，只承担素材维护和预填职责。

## 6. 后端接口与 Socket 事件

### 6.1 HTTP 接口

#### 健康检查

```http
GET /api/health
```

响应：

```json
{
  "ok": true,
  "time": 1790000000000
}
```

#### 获取题库校验报告

```http
GET /api/questions/validation
```

响应：

```json
{
  "validCount": 18,
  "invalidCount": 2,
  "items": [
    {
      "id": "1",
      "valid": true,
      "errors": []
    }
  ]
}
```

#### 获取题目列表

```http
GET /api/questions
```

仅管理后台使用。返回题目元信息和资源 URL，不返回隐藏字段以外的服务器路径。

#### 保存题目信息

```http
PUT /api/questions/:questionId/info
Content-Type: application/json
```

要求：

- 服务端校验 JSON schema。
- 保存前写入临时文件，再原子替换。
- 保存后重新校验该题。

#### 上传题目图片

```http
POST /api/questions/:questionId/assets
Content-Type: multipart/form-data
```

字段：

- `file`：图片文件。
- `kind`：`questionImg` 或 `answerRevealImg`。

#### 上传资源包

```http
POST /api/questions/import-zip
Content-Type: multipart/form-data
```

规则：

- 解压到临时目录。
- 校验没有路径穿越。
- 仅允许写入 `server/resource/question` 内。
- 导入题目与当前题库取并集，并将新题目 ID 注册到 `catalogue.json`。
- 遇到已存在的题目 ID 时保留现有题目，并在导入报告中标记冲突。
- 返回导入报告。

#### 外部提交答案

```http
POST /api/game/submit-answer
Content-Type: application/json
```

请求：

```json
{
  "userName": "外部用户1",
  "answer": "答案"
}
```

响应：

```json
{
  "accepted": true,
  "correct": false,
  "message": "答案已接收"
}
```

### 6.2 Socket.IO 客户端事件

客户端发送：

| 事件名 | 说明 |
|---|---|
| `room:create` | 创建房间 |
| `room:join` | 加入房间 |
| `room:leave` | 离开房间 |

服务端广播：

| 事件名 | 说明 |
|---|---|
| `room:snapshot` | 房间完整快照 |

| `game:scoreboard` | 最新计分板 |
| `game:overtimeStart` | 加时赛开始 |
| `game:settle` | 排名结算 |
| `game:backToIdle` | 回到等待开局 |

## 7. 题库与资源管理

### 7.1 目录约定

```text
server/resource
├─ catalogue.json
├─ full_data/
│  ├─ evidence-wall.png
│  ├─ evidence-wall.json
│  ├─ investigator.png
│  └─ investigator.json
└─ question_data/
   ├─ evidence-wall-01.json
   └─ investigator-01.json
```

### 7.2 校验规则

题目必须满足：

1. `catalogue.json` 是索引对象数组，ID 和记录路径唯一。
2. 索引引用的单题 JSON 位于 `question_data` 内。
3. 文件名、索引 ID 和单题记录 ID 一致。
4. 启用题目的标题和 `answers` 完整。
5. `originalImage` 对应 `full_data` 中存在的图片。
6. `question` 裁切框尺寸为正、位于记录的原图尺寸内。
7. 图片扩展名只允许：`.jpg`、`.jpeg`、`.png`、`.webp`、`.gif`。
8. `difficulty` 若存在，只能包含 `simple`、`medium`、`hard`、`hell`。
9. `enabled === false` 的题目可以不完整，但不进入游戏抽题池。

图片职责：

- 每张原图只保存一份，不再生成或维护 `question.png`。
- 题面由 `question` 中的原图像素裁切坐标描述。
- Phaser 在答题阶段对原图纹理应用裁切框，揭晓阶段恢复完整原图。

### 7.3 管理后台功能

MVP 管理后台页面：

1. 左侧可在原图视图和题目视图之间切换。
2. 原图视图直接枚举 `full_data`，显示文件名及有效、异常、总题数，悬停显示原图缩略图。
3. 展开原图后显示关联题目，并在原图旁提供新增题目按钮。
4. 新题读取同名 JSON 预填答案、提示、难度和标签，但标题与裁切框保持为空，完成前不落盘。
5. 题目视图按 catalogue 展示全部题目，悬停显示实时裁切谜面缩略图。
6. 详情表单编辑单题 JSON，同时展示完整谜底、裁切器和裁切谜面预览。
7. 保存只提交题目字段和裁切坐标；上传原图只写入 `full_data`。
8. 支持按标题、答案、标签、原图文件名和校验状态筛选。
9. 运行题库校验并展示错误，支持新格式整库导入导出。

删除规则：

- MVP 不提供物理删除题目目录。
- 提供 `enabled=false` 禁用题目。
- 物理删除作为后续迭代，避免误删资源。

## 9. Phaser 渲染职责

Phaser 不做业务判定，只消费 Vue/Socket 传入的状态。

### 9.1 场景职责

建议实现一个主场景：

```typescript
class GuessScene extends Phaser.Scene {
  preload(): void;
  create(): void;
  update(time: number, delta: number): void;
}
```

场景需要支持的命令：

| 命令 | 说明 |
|---|---|
| `showQuestion` | 展示谜题图 |
| `showCorrectFeedback` | 答对动画 |
| `showWrongFeedback` | 答错动画 |
| `showTimeoutFeedback` | 超时动画 |
| `showReveal` | 展示完整图和答案 |
| `setCountdown` | 设置倒计时视觉 |
| `destroy` | Vue 页面卸载时释放资源 |

### 9.2 Vue 与 Phaser 边界

- Vue 组件创建 Phaser 实例。
- Vue 监听 Socket 或单人本地状态后调用 Phaser 场景方法。
- Phaser 内不直接调用后端接口。
- Vue 组件卸载时必须调用 `game.destroy(true)`。

## 11. 安全、容错与性能要求

### 11.1 文件安全

- 所有文件写入必须限制在 `server/resource` 内，并严格限制到 `full_data` 与 `question_data` 子目录。
- 处理上传文件和 zip 解压时必须使用路径归一化，拒绝 `../` 路径穿越。
- 上传文件名由服务端生成或清洗，不信任客户端文件名。
- 只允许图片和 zip 的白名单扩展名。
- 限制上传大小，默认单文件不超过 10 MB，zip 不超过 100 MB。

### 11.2 接口安全

- 外部答案接口只在一个外部接口房间处于 `PLAYING` 或 `OVERTIME` 时接受请求。
- 外部玩家仅按规范化后的昵称识别。
- 房主操作必须校验 `playerId === hostPlayerId`。
- 不能让客户端提交分数、题目 ID 或判题结果。

### 11.2.1 管理后台访问

- 访问题库后台前必须输入管理密码。
- 密码通过服务端配置文件提供，不写入前端代码，也不使用数据库。
- 登录成功后签发仅用于当前服务实例的短期管理会话。

### 11.3 容错

- 题库中坏题不影响服务启动。
- 当前题图片加载失败时，服务端可跳过该题并记录错误。
- 普通玩家断线后保留分数；重连通过客户端 session ID 恢复。
- 房主离开后房间立即销毁，所有玩家返回主界面。
- 房间长时间空闲可设置 TTL，例如 2 小时。

### 11.4 性能

- 启动时只读取轻量 catalogue、注册的单题 JSON 和原图文件名，不加载图片二进制。
- 图片通过静态文件 URL 提供。
- 地狱难度和多人模式应预加载下一题图片 URL。
- Socket 广播使用房间维度，不做全局广播。

### 11.5 部署边界

- 首版仅面向可信局域网部署，不承诺公网暴露时的安全强度。
- 服务监听地址可配置为 `0.0.0.0`，方便同一局域网设备访问。
- 暂不强制 HTTPS、公网反向代理、分布式限流或持久化会话。

## 12. MVP 实现顺序与验收标准

### 12.1 第一阶段：项目骨架

实现内容：

- 根目录 npm scripts。
- `server` Express + Socket.IO 启动。
- `web` Vite + Vue + Phaser 最小页面。
- 前后端本地联调。

验收：

- `npm run dev` 能同时启动前后端。
- 浏览器能打开首页。
- Phaser 画布能正确创建和销毁。

### 12.2 第二阶段：题库模块

实现内容：

- `catalogue.json` 读取。
- `info.json` schema 校验。
- 答案匹配模块。
- 静态图片服务。

验收：

- 坏题不会导致服务崩溃。
- 校验报告能准确列出错误。
- 答案中的全部空白字符会被忽略，其余内容精确匹配。

### 12.3 第三阶段：单人模式

实现内容：

- 单人配置页。
- 单人游戏状态。
- 倒计时、生命、计分、结算。

验收：

- 四种难度时间正确。
- 超时扣生命，答错不扣生命。
- 快速答对加生命但不超过 10。
- 生命为 0 时结束。

### 12.4 第四阶段：多人房间

实现内容：

- 创建房间、加入房间。
- 房主开始。
- Socket 抢答。
- 计分板和排名。

验收：

- 20 人上限生效。
- 开始后不能加入。
- 第一个答对玩家得分。
- 同题后续答案不会重复计分。
- 结算后房间回到 `IDLE`。

### 12.5 第五阶段：外部接口和管理后台

实现内容：

- 外部答案 HTTP 接口。
- 唯一活动外部接口房间校验。
- 管理后台题目列表、编辑、上传、校验。

验收：

- HTTP 提交答案进入同一套多人判题逻辑。
- 外部用户能出现在计分板。
- 管理后台保存后立即重新校验。
- zip 导入不自动污染 `catalogue.json`。
